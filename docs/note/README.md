# note 入稿用のメモ

`word-basket-note-article.md` は、note にそのまま貼れる形で書いてあります。
画像は `images/` に21点入っています。

## 貼るまえに直すところ

一つだけあります。タイトル行の連載番号です。

```
# 教室で使えるかもしれないもの作り #◯ 「順番が来るまでひま」をなくす。全員でいっせいにことばを探すカードゲームアプリ「ワードバスケット」
```

`#◯` を実際の番号に置きかえてください。推測で埋めていません。

## note への入稿手順

1. note で新しい記事を作り、上のタイトル行から `# 教室で使えるかもしれないもの作り` の見出し記号を外したものをタイトル欄に入れる
2. 本文は `## 🏫 はじめに` から最後までを貼る。見出しは note の見出し2として認識されるので、目次が自動で作られる
3. 画像は貼れないので、`images/` のファイルを本文の `![...](images/xx.png)` が置かれている位置に手で挿入する。ファイル名の番号が本文に出てくる順番と同じにしてあるので、01 から順に上げていけば迷いません
4. 画像の直後に置いてある一行を、note のキャプション欄に移す。本文に残しても読めますが、キャプションに入れたほうが記事が締まります
5. 記事の URL は本文中に1回だけ出しています。note の埋め込みカードにする場合は、その行を空行だけの行に貼り直してください
6. ハッシュタグは #GIGAスクール #ICT教育 #小学校 #学級レク #自作アプリ あたりを想定しています

## 記事に書いた数字の出どころ

- カード59枚。`src/App.jsx` の `FULL_DECK_DEF` を数えたものです。実機でも裏を取っています。2人で始めると山札が48枚、4人で38枚、6人で28枚と表示され、いずれも 59 引く 5かける人数 引く 1 に一致します
- ひらがな44枚。あ行からわまでを数えたもので、濁点、半濁点、小さく書く文字、そして「ん」は入っていません
- 行のカード9枚。あ行、か行、さ行、た行、な行、は行、ま行、や行、ら行です
- 文字数のカード6枚。5文字が2枚、6文字が2枚、7文字以上が2枚です
- 人数は2人から6人、制限時間はなし、10秒、15秒、20秒、30秒。どちらも遊ぶ準備の画面の選択肢そのままです
- 手札は5枚。ゲーム開始の処理で5枚ずつ配っていて、画面の「残り 5枚」でも確認しました
- 残り3秒で赤くなること。`13-timer-red.png` が実際にその状態です
- 2回目からオフラインで動くこと。アプリを開いたあと通信を完全に切って読み直し、遊ぶ準備の画面が出て操作できることを確かめました
- カードを上へはらって出せること。タッチのある端末として開き、手札を90ピクセルぶん上へ動かしたところ、手札が1枚減って場札がそのカードに変わりました
- 何も保存せず、遊んでいるあいだは通信しないこと。`src/` に保存や通信の処理が1か所もないことを確かめました。通信はアプリ本体の読みこみと、文字の形の読みこみだけです
- フィルタリングで許可する3つのアドレス。公開先の `gigayama.github.io` と、`index.html` が読んでいる `fonts.googleapis.com`、`fonts.gstatic.com` です

確かめていないので記事に書かなかったことも残しておきます。撮影は Chromium で行ったので、iPad の Safari や Chromebook の実機での見え方は確認していません。
ホーム画面に追加する操作そのものも、端末ごとの手順は踏んでいません。オフラインで動くことは確認済みです。

## 撮り直すときの手順

`node_modules` の解決の都合で、撮影用のシナリオはリポジトリの中に置くことになります。
`.tmp-shots/` という名前で作って、納品時に消しました。同じ手順でやり直せます。

```bash
npm i --no-save playwright
npm run build
node <スキルの置き場>/scripts/serve.mjs dist 4180 /word_basket/
node <スキルの置き場>/scripts/capture.mjs .tmp-shots/shots.mjs \
  --base http://127.0.0.1:4180/word_basket/ --out .tmp-shots/out
```

撮るときに気をつけたところが4つあります。

1つ目は文字の形です。このアプリは Zen Maru Gothic という丸い書体を Google Fonts から読んでいます。
撮影した環境からはブラウザが直接そこへ出られなかったので、書体のファイルだけを先に取ってきて
`dist/fonts/` に置き、`dist/index.html` の読みこみ先をそこへ向けてから撮りました。
`dist/` は git の管理外なので、リポジトリには何も残っていません。
これをしないと書体が別のものに置きかわって、本番と見た目が変わります。

2つ目はボタンではないものを押すやりかたです。手札のカードと山札は button ではないので、
文字で押す仕組みでは当たりません。クラス名で拾って押しています。
このとき、要素を画面の中央に寄せる動きを一緒にやってしまうと、プレイ画面の中身がまるごとずれて写ります。
プレイ画面では、寄せる動きなしで押してください。

3つ目はお知らせの表示です。パスや時間切れのお知らせは2秒で消えます。
続けて別の画面を撮ると前のお知らせが写りこむので、2.5秒ほど置いてから撮りました。

4つ目は特別なカードを場に出すやりかたです。どのカードが出るかは毎回変わるので、
場札の文字を読んで、目当ての種類になるまでパスをくり返す形にしました。

## 文体について踏襲したこと

連載の書きかたに合わせて、次を守っています。

- 太字、斜体、表を使っていません。矢印や全角の記号も使っていません。確認したところどれも0件です
- Markdown は見出しだけです。箇条書きは使い方のガイドの手順だけで、それ以外は文章で書いています
- 専門用語を出していません。公開の設定、通信、端末のなかに残る、といった日常の言葉に置きかえています
- 絵文字は見出しだけです
- 見出しは基本の6つに、特別なカードの節と秒読みの節を足した8つです。目玉が2つあったので2本まで足す形にしました
- 教室での出来事を実体験として書いていません。「こうなればいいと思って作った」「〜だと思います」までにとどめています
- 効果を言い切っていません。導入のメリットの節も、期待できることとして書いています
- 本文は約7,200字です

作者本人が書く連載なので、機能の説明だけでなく「なぜそう作ったのか」「あえてしなかったこと」を各節に入れています。
3文字以上にした理由、手札を5枚にした理由、正誤の判定を入れなかった理由、記録を残さない理由がそれです。
ここは書き手のものなので、違う考えがあれば書きかえてください。

実際の授業でどうだったかは書けないところなので、そこは書き手が足す部分として空けてあります。
まとめの前あたりに一段落入ると、記事の重みが変わると思います。
